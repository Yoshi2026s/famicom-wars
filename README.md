# ファミコンウォーズ

## メインマップ「はじまりの草原」

[GitHub Pages で遊ぶ](https://yoshi2026s.github.io/famicom-wars/)

「はじまりの草原」は、歩兵や車両の部隊を指揮する14列×10行のメインマップです。ゲームを開くとそのまま対戦を始められます。以前のリンクからも同じマップが開きます。

iPhoneのSafariでは、共有メニューの「ホーム画面に追加」から専用アイコンを置けます。Safariに保存した対戦の続きをホーム画面から開く場合は、「Webアプリとして開く」が表示されたらオフにして、ゲームのページを追加してください。AndroidのChromeでは、メニューからウェブサイトのショートカットを作れます。

スマホは縦向きでタップ操作します。横向きでは案内が表示され、縦向きに戻すと続きから遊べます。キーボードではTabで盤面に入り、矢印キーとEnterまたはスペースで操作します。

攻撃が成立すると戦闘画面に切り替わります。攻撃する側のHPが8〜10なら3、4〜7なら2、1〜3なら1が基礎ダメージです。先に攻撃を受けた側が生き残り、相手が射程内にいれば、被弾後のHPで1回反撃します。ダメージの上限は相手の残りHPです。「演出をスキップ」で結果を確認し、「マップに戻る」で続行できます。

戦闘画面では「先攻」「反撃」を表示します。歩兵は隊列で一斉射撃、偵察車は機銃を連射、支援車は弧を描く支援弾を発射し、戦車は主砲の反動でカメラが揺れます。被弾や撃破では、歩兵が伏せる動き、偵察車の横滑り、支援車の発射機から上がる煙、戦車の装甲から散る火花といった兵種別の演出が出ます。端末の「動きを減らす」が有効な場合は画面の動きを抑え、HPと結果を表示します。

手番が変わると画面中央に手番名が出ます。マップと戦闘画面の「効果音」で、手番切替音・射撃音・着弾音をオン・オフできます。対応ブラウザーでは射撃側と着弾側に合わせて音の左右が切り替わります。演出をスキップすると、残りの戦闘音は停止します。

「BGM」は効果音とは別に設定します。味方の手番はフルートとハープの明るい旋律、敵の手番は低音の弦と太鼓が目印です。戦闘曲も手番ごとに分かれ、同じ手番の戦闘後はマップ曲の続きに戻ります。勝利時は金色の旗と上昇するファンファーレ、敗北時は青灰色の戦場と下降する旋律で結果を表示します。それぞれの決着曲は一度だけ流れ、勝敗画面は「マップに戻る」を押すまで表示します。画面を離れると一時停止します。

BGMと効果音の初期設定はどちらもオンです。BGMは最初のタップやクリックから再生されます。選んだ設定は同じブラウザーに保存されます。

## 対戦の進め方

進行は、部隊の移動・戦闘・生産やターンの進行に合わせて、同じブラウザーに自動保存されます。iPhoneのSafariでは通常タブでゲームを開き直すと、続きから遊べます。戦闘演出の途中で閉じた場合は確定した戦闘結果から、敵ターンの途中なら残りの敵の行動から再開します。Safariのサイトデータを消去すると保存も消えます。

スマホ縦画面では、盤面を上下左右にスワイプできます。座標の見出しは固定され、部隊の現在HPはマス上で確認できます。「次の部隊」は行動できる味方へ切り替え、「味方部隊」では一覧から選べます。「全体図」の白枠は現在の表示範囲です。地図や本拠地のボタンを押すと、表示場所を移動できます。「戦況」には敵部隊・資金・施設の状況、行動履歴、地形の凡例、音声設定があります。

川は隣り合うマスで岸がつながり、橋の下にも水面が流れます。移動確認では経路が光り、確定した部隊は兵種ごとの動きでマスを進みます。待機中は歩兵が見張り、偵察車のアンテナが揺れ、支援車は発射機を上げ下げし、戦車は砲身を動かします。占領・出撃・施設回復は盤面上で光ります。端末の「動きを減らす」を有効にすると、マップの水面や部隊のアニメーションを抑えます。

味方はB7に偵察車、D2に歩兵、C2に支援車が出撃します。敵はH2に歩兵、H6に偵察車、H3に支援車が出撃し、全員HP10で始まります。盤面かマップ上の部隊一覧で、動かす部隊を選びます。味方はそれぞれ1ターンに1回まで移動し、移動後も射程内の敵を攻撃できます。攻撃するとその部隊の行動が終了します。部隊一覧で双方のHPを確認でき、行動指示には敵の移動先と攻撃対象が表示されます。

移動・占領は行き先と消費移動力、攻撃は攻撃と反撃によるHPの変化を確認してから実行します。「生産」の印があるマスを選ぶと、その工場で購入できるユニットが出ます。選択中の部隊がそのマスへ移動できる場合は、同じ画面から移動を選べます。

歩兵は移動力2、偵察車は移動力4で、射程はどちらも1マスです。支援車は移動力1で、射程は上下左右で数えた距離2〜3マスです。戦車は移動力3・射程1で、攻撃と反撃の基礎ダメージが通常より1高くなります。相手が自分の射程内にいれば、攻撃を受けた直後に反撃できます。

敵のターンは出撃順に、生き残っている部隊が移動と攻撃をそれぞれ1回まで行います。全員の行動が終わると味方のターンに戻ります。

敵の手番では、盤面が行動中の部隊を追い、移動経路を1マスずつ表示します。敵の行動欄には移動・攻撃・占領・待機のうち実行する操作が表示されます。敵工場が生産するときは、選んだユニット・費用・出撃する工場を確認できます。

画面上部に「味方の手番」または「敵の手番」が表示されます。マップ上では「済」が行動済み、「攻可」が移動後も攻撃可能、「次」が次のターンから行動可能、「動」が行動中の敵を示します。部隊一覧でも行動状況を確認できます。

川や他の部隊がいるマスは通れません。F2・E6・E9にある橋を使うと、対岸まで進めます。湿地は移動力を2消費します。攻撃・反撃で受けるダメージは森と湿地で1、山で2減り、最低1になります。

味方の本拠地はA7、敵の本拠地はN8です。歩兵を空いている敵本拠地へ移動させると、その場で占領して勝利します。敵歩兵に味方の本拠地を占領されると敗北です。いずれかの陣営が全滅した場合も決着します。「もう一度対戦する」で初期配置から再挑戦できます。

都市は4つあります。C4は味方、H5は敵が所有し、E2とF6は中立から始まります。歩兵を空いている都市に移動させると占領できます。初期資金は各陣営4,500で、2ターン目以降は毎ターンの開始時に所有都市1つにつき1,000が入ります。同時に、自軍の都市や工場にいる生存部隊はHPを2回復します（最大10）。

工場はB6とI5にあり、最初はそれぞれ味方と敵が所有します。歩兵が空いている相手の工場に移動すると占領できます。占領した歩兵などがマスを空けると、同じ工場から自軍の部隊を生産できます。自軍の工場はそれぞれ1ターンに1部隊を生産でき、費用は陣営の共通資金から支払います。費用は歩兵1,000、偵察車2,500、支援車3,000、戦車4,000です。

スマホでは、画面下の「ユニット生産」から生産する工場と部隊を選べます。「ターン終了」も画面下に固定されます。PCでは行動指示の「味方工場」で生産します。敵も占領した工場を使い、敵ターンの最後に生き残っている数が最も少ない種類を補充します。新部隊は生産した工場にHP10で出撃し、次のターンから移動と先制攻撃ができます。

キーボードでは矢印キーで画面外のマスにも移れます。

## ローカル開発

Node.js 24 を使います。追加パッケージのインストールは不要です。

```powershell
node --version
node --test
node dev-server.mjs
```

ブラウザーで http://127.0.0.1:8080/ を開きます。終了するにはターミナルで Ctrl+C を押します。

- `public/` にブラウザーへ配信する HTML、CSS、JavaScript、素材を置きます。
- `test/` に自動テストを置きます。変更後は `node --test` を実行します。

- 盤面・補助背景・部隊やホーム画面アイコンのドット絵の編集元は `scripts/draw-assets.mjs` です。`node scripts/draw-assets.mjs` でPNGを再生成できます。4兵種の戦闘用画像は待機・構え・発射・反動・被弾・防御・撃破の7コマを1ファイルに格納しています。
- 戦闘背景 `public/assets/highland-dusk.webp` は組み込みの画像生成で制作し、WebPに変換した素材です。
- BGMの曲データとMP3生成は `scripts/compose-bgm.mjs` にあります。`pnpm install --frozen-lockfile` で生成用の依存関係を取得し、`node scripts/compose-bgm.mjs` でオリジナルの6曲を再生成できます。

## GitHub Pages への公開

1. 公開先の GitHub リポジトリに `main` を push します。
2. リポジトリの **Settings → Pages → Build and deployment → Source** で **GitHub Actions** を選びます。
3. **Actions → Test and deploy to GitHub Pages → Run workflow** から `main` を選んで初回配信します。配信ジョブが成功したら、ジョブに表示される公開 URL を開いて確認します。

以降は `main` 向けのプルリクエストでテストを実行します。`main` に反映した変更は、テスト成功後に `public/` の内容を自動配信します。プロジェクト用の Pages URL でも動くように、HTML 内の素材リンクは相対パスで指定します。
